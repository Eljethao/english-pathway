# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

English Pathway is a static learning site that takes English learners from B1 to C1 and prepares them for IELTS, TOEFL iBT and TOEIC. It runs on Next.js 16 (App Router, `cacheComponents: true`), React 19, Tailwind CSS v4, and optional Supabase for sign-in and progress sync. Next.js 16 differs from older versions: read the guides in `node_modules/next/dist/docs/` before changing routing, caching or data-fetching code.

## Commands

```bash
npm run dev          # http://localhost:3000
npm run build        # production build; every page is prerendered
npm run lint
npm run typecheck    # tsc --noEmit for the whole app
npm run validate     # content validator for all lessons, practice sets and placement

node scripts/validate-content.mts <slug-or-skill>   # validate one lesson (substring match) or one skill; also "practice" / "placement"
npx tsc -p tsconfig.content.json                    # type-check content files only
node scripts/gen-lesson-index.mts                   # regenerate src/content/lessons/index.ts
```

There is no unit test framework. The content validator and the type checkers are the checks. Scripts are `.mts` files that Node runs directly with type stripping; they import `.ts` sources from `src/` by relative path.

## Architecture

**Content is data, not a CMS.** All course material lives in TypeScript under `src/content/`. `src/lib/types.ts` defines and documents every field (`Lesson`, `Section`, `Exercise`, `PracticeSet`, `Progress`…). `src/lib/content.ts` is the only read layer the pages use: it sorts lessons by skill, then level, then order, and exposes lookups, courses, summaries and vocabulary lists.

**Lessons: manifest → files → generated index.**
- `src/content/lessons/manifest.ts` is the curriculum: 4 skills × 3 levels × 12 lessons. Slug, skill, level, order and title are fixed there.
- Each lesson is one file, `src/content/lessons/<skill>/<slug>.ts`, with a default export and `import type` only.
- `src/content/lessons/index.ts` is generated by `gen-lesson-index.mts`. Never edit it by hand.
- To add a lesson: add it to the manifest, write the file, regenerate the index, then validate. `CONTENT_GUIDE.md` holds the authoring rules: section and exercise kinds, body-text markup, TTS transcript format, exact exam task names, word counts and timings. Read it before writing or editing content. `docs/review/RUBRIC.md` is the quality bar.

**What the validator enforces** (`scripts/validate-content.mts`), beyond what types catch:
- Answer indexes in range, `{{n}}` gap placeholders matching `answers`, no duplicate exercise ids within a lesson.
- Lesson shape: 1–2 warm-up questions, 8–12 vocabulary items, at least 2 exercises. Lessons 5–11 need at least 4, lesson 12 at least 3.
- Every complete 12-lesson course must total at least 240 minutes.
- Audio transcripts: every `Speaker:` needs a gender in `cast`, unlabelled lines need `cast.narrator`, and a speaker who says "This is Kenji" must have a voice of matching gender.
- `image` sections must point to a file that exists in `public/`.

**Rendering.** Pages are Server Components that read content at build time and use `generateStaticParams`. Dynamic routes wrap their async body in `<Suspense>`, as required under Cache Components. Interactivity lives in client components under `src/components/`.
- `/lessons/[slug]` is the overview. `/lessons/[slug]/learn` is the step-by-step player.
- `src/lib/lesson-steps.ts` turns `learn` / `model` / `practice` into player screens. Stimulus sections (passage, audio, chart, table, image) stay grouped with the exercises that follow them.
- `src/components/lesson/SectionRenderer.tsx` renders sections. `src/components/exercises/Exercise.tsx` dispatches on `exercise.kind`.
- MCQ options are shuffled deterministically per question. `src/lib/shuffle-options.ts` keeps the written order for fixed sets, numbers, labels, and options or prompts that refer to an option by letter.

**Progress is client-only.**
- `src/lib/progress.ts` is a small external store over `localStorage` (key `english-pathway:progress`), read through `useSyncExternalStore` in `src/hooks/useProgress.ts`. The server snapshot is always empty progress, so anything that depends on progress must tolerate an empty first render. `useHydrated()` helps with that.
- Exercise scores are keyed `<lesson-slug>/<exercise-id>` via `ExerciseScope` in `src/components/exercises/ExerciseShell.tsx`. Renaming an exercise id orphans learners' saved scores.
- Flashcards use Leitner boxes. Progress can be exported and imported as JSON.

**Cloud sync is optional and browser-only.**
- `src/lib/cloud.ts` creates a Supabase client only when `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are set. Without them, sign-in disappears and everything else works the same.
- Sign-in supports email and password, magic links, and password reset at `/auth/reset`. Auth uses the PKCE flow and lands on `/auth/callback`.
- Email links always use `SITE.url` from `src/lib/meta.ts`, which comes from `NEXT_PUBLIC_SITE_URL` and defaults to `https://english.ljthao.com`.
- Each user has one `progress` row of JSONB protected by row-level security, defined in `supabase/migrations/`. On sign-in, local and remote progress are merged by `mergeProgress`. After that, changes upload after a short delay and again when the tab becomes visible. `CloudSync`, mounted in the root layout, starts the engine.
- Never put a service-role key in a `NEXT_PUBLIC_` variable.

**AI speaking feedback is the only server code.**
- `POST /api/speaking-feedback` lives in `src/app/api/speaking-feedback/route.ts`. It takes a WAV recording plus the target sentence or task, asks Gemini for pronunciation, accent and fluency feedback, then cleans the JSON. For listen-and-repeat, it also adds target words that are missing from the transcript, using its own word comparison.
- `src/lib/gemini.ts` is server-only and reads `GEMINI_API_KEY` and `GEMINI_MODELS`. It tries the models in order, moving on after a 404, 429 or 5xx.
- **Use free-tier models only (project decision).** Never add a Pro model to `GEMINI_MODELS`; the helper also filters "pro" out.
- None of the approved models can output audio. Listening therefore stays on browser text-to-speech, and Gemini's separate "-tts" models are not used.
- The browser side lives in `src/lib/ai-feedback.ts` and `src/components/media/AiFeedback.tsx`. Recordings are converted to 16 kHz mono WAV before upload, because MediaRecorder produces WebM or MP4 depending on the browser.
- Four modes share the route. `speak` handles speaking tasks. `shadow` handles listen-and-repeat. `say` handles multiple-choice questions with a `say` field, and checks the recording against the correct option, such as a stress pattern, a sound or the stressed word. `choose` serves multiple-choice exercises with `answerBy: "voice"`: it asks which option the learner said, without telling the model the answer, and the client uses that option as the learner's choice. Learners say only the word. In tests on clear synthetic speech, the word alone scored 10–14 of 16 across runs, against 12–13 for the whole sentence, where the model guesses the likelier sentence. Asking for IPA first scored worse. Errors repeat on the same pairs (van/fan, light/right, taught/thought), and Gemini overload often makes calls fail, so the exercise always offers "Choose the words instead".
- Stress judgements are the weakest part. Telling the model the target works better than asking it to choose among the options, which makes it always pick the dictionary form. Even so, it sometimes marks correct stress as wrong.
- A recording is uploaded only when the learner presses an AI button or answers a voice question (sent on Stop, with a notice above the exercise). The About page says so. Keep that statement true.
- The route has an origin check and an in-memory limit per IP. It needs a server runtime, not a static export.

**Browser media.**
- Listening uses the Web Speech API (`src/lib/speech.ts`), which picks a voice per speaker from `cast`. An `audio` section with `src` plays a real file from `public/audio/` instead.
- Speaking uses `MediaRecorder` plus `SpeechRecognition` where the browser supports it.

**Images.** `next/image` uses a custom loader (`src/lib/image-loader.ts`). Decorative photos come from the Pexels CDN, listed in `src/lib/photos.ts`. Lesson diagrams and maps are hand-made SVGs in `public/images/`, named after the lesson slug.

## Conventions

- The import alias `@/*` maps to `src/*`.
- Exam formats, timings and score scales live in `src/content/exams.ts`, last verified in October 2026. Treat that file as the source of truth, and update it there when a test format changes.
- All content must be original. Never copy or closely paraphrase official Cambridge, IDP, British Council or ETS material.
- The README is partly out of date. It mentions 48 lessons and magic-link-only sign-in, but there are now 144 lessons and password sign-in.
